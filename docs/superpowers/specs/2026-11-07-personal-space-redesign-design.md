# 个人空间改版 · 设计文档

日期：2026-11-07
状态：v2 待评审

## 0. 变更记录

**v1** 的视觉语言是「信笺与邮戳」：道林纸底、宋体抬头、邮戳蓝主色、朱红日期章、齿孔。阶段 1 按它实现并验收通过后，站长否掉了——米色纸底 + 宋体 + 朱红这一组读起来仍是模板站的暖色默认，而且整个界面是静态的，没有生气。

**v2** 改为「观测台 / 实时仪表」：暗色为默认，界面是一套读得通的仪器，每一处动效、每一个读数都必须有数据源。内容不变——观测的是生活，不是系统。

v2 改动：§1、§2（整节重写）、§4（整节重写）、§5.1、§5.4、§5.5、§6.3、§10、§11、§12、§13。其余沿用 v1。

## 1. 目标与非目标

### 目标

把一个以技术文章为主轴的博客，改造成以「生活流」为主轴的**个人空间**：

- 访客打开首页，先看到这个人最近在过什么生活，而不是最新一篇技术文章。
- 发布压力要低——一两句话加一张照片就能发一条。
- 访客能参与：评论、在信箱留言、推荐歌。
- 视觉要有辨识度，且不像模板站或 AI 生成：界面是一套仪器，动效全部有数据源，没有源就不显示。
- 打开首页两秒内知道这个人「此刻」是什么状态——本地时间、天气、密度、连续性、在听什么在读什么。

### 非目标

- 不做社交网络。没有关注、私信、转发、点赞排行。
- 不做多用户内容平台。访客只能评论和留言，不能发帖。
- 不做音频托管。歌单只做卡片 + 跳转外部音乐平台。
- 不做实时通知、推送。

### 一句话定位

> 赵小元的个人空间：记录生活，收信，听歌，看书。

## 2. 视觉系统：观测台

### 2.1 取材

一台**自己给自己装的观测仪**：面板、硬线、读数、状态灯。物件是真实的——这个人在过日子的痕迹，不是想象中的仪表。

明确不取的东西：赛博朋克、霓虹、极光渐变、扫描线、玻璃拟态。它们的共同问题是**没有数据源也要动**，那正是 §2.6 要禁止的东西。材质感来自密度和对齐：读数够真够密、栅格够硬，它就像仪器；加一层模糊或渐变，它就像模板。

### 2.2 颜色

两套模式，同一套语义。**默认是观测台（暗）**；「报表模式」（亮）是同一块面板打印出来的样子，不是附属主题。

| Token | 观测台 | 报表模式 | 用途 | 对比度（对最深的一层底） |
| --- | --- | --- | --- | --- |
| `--background` | `#0d0f12` | `#f5f5f3` | 页面底 | — |
| `--panel` | `#14171c` | `#ffffff` | 面板、读数卡 | — |
| `--panel-2` | `#1a1e24` | `#ecece8` | 面板内的凹陷区（读数格、热图底） | — |
| `--foreground` | `#e8eaed` | `#12141a` | 正文 | 13.88 / 15.54 |
| `--muted-foreground` | `#8b9099` | `#5a6068` | 标签、单位、批注 | 5.22 / 5.36 |
| `--rule` | `#262b32` | `#d9dce1` | 唯一分隔手段，1px 实线 | 非文字，不适用 |
| `--ok` | `#46a37a` | `#2b7655` | 在线、已完成、已通过 | 5.40 / 4.63 |
| `--data` | `#6f9bd1` | `#2b5c93` | 读数、链接、折线 | 5.80 / 5.80 |
| `--wait` | `#cea04c` | `#88631d` | 待审、进行中 | 6.98 / 4.61 |
| `--alert` | `#c66e5c` | `#9e4a3b` | 告警、失败、未读 | 4.61 / 5.07 |

右列是 WCAG 相对亮度比，「对最深的一层底」指 `--panel-2`（暗）与 `--panel-2`（亮）——文字落在哪一层都不许跌破 4.5:1。这几个数是调过的，不是挑了好看的颜色再补一句「要注意对比度」。

约束（硬）：

- 四个语义色的含义固定，不得挪用。颜色出现在某处，读者必须能推出它代表哪个状态；推不出就是错。
- **彩度上限 OKLCH `C ≤ 0.12`**（上面十个色实测 0.091–0.116）。这是「不像霓虹」的可测量形式；换成 HSL 说不清，也不许用「看着不刺眼就行」代替。
- 任何语义色不做按钮底色、不大面积铺、不进渐变、不做投影色。
- 不用阴影分层。层级只靠 `--background` → `--panel` → `--panel-2` 的亮度差和 1px `--rule`。
- 正文永远是无彩度的 `--foreground`。
- 这些比值要能被机器复查：`scripts/tokens.test.mjs` 除了现有的存在性断言，还要从 `globals.css` 解析出上述 token，按 WCAG 公式断言「正文 ≥ 7:1、语义色与弱字 ≥ 4.5:1（相对 `--panel-2`）」，并断言彩度 ≤ 0.12。改色就红灯，比写进文档管用。
- 实现继续以 shadcn 的变量名作底层（`--background`、`--foreground`、`--card`、`--muted`、`--muted-foreground`、`--border`、`--primary`…），只换值；`--panel`、`--panel-2`、`--rule`、`--ok`、`--data`、`--wait`、`--alert` 作为语义别名新增。旧组件先跟着底层名字走，不一次性全改。
- 退役 v1 专用的 `--stamp`、`--postmark`、`--vermilion`、`--paper-raised` 四个变量，以及 `.paper-sheet`、`.postmark`、`.perforated` 三个类。
- `--chart-1..5` 从「在 `globals.css` 里定义了两次、全栈零引用」改绑到 `--data`、`--ok`、`--wait`、`--alert`、`--muted-foreground`；折线与热图必须走这套 token，不许写死 hex。
  - 已实现的 90 天热图只用 `--data` 一色、按密度调透明度，不铺四种语义色——用四个语义色表示「今天提交多/少」会把固定含义挪作强度编码，违反上面的含义固定规则。`--chart-*` 保留为将来折线图的通用系列调色板。

### 2.3 字体

| 角色 | 字体 | 说明 |
| --- | --- | --- |
| 站名、月份标题、单条动态正文 | 思源宋体（Noto Serif SC） | 仪器里唯一「人」的痕迹，用量极小 |
| 读数、标签、单位、时间戳 | Geist Mono / 等宽 | 全大写英文标签 + 中文值，双语标签像进口仪器 |
| 界面正文、说明 | 系统无衬线 | |
| 手写体 | **不使用** | 中文字体包体积大，且「手写体点缀」是最常见的滥用套路 |

字号与规则：

- 读数主体 24–32px；标签 10–11px、mono、`letter-spacing: 0.14em`、全大写；中文值不加大字距。
- **所有数字一律 `font-variant-numeric: tabular-nums`**。走秒的数字用比例数字会抖，这是仪器最便宜的破绽。
- 站名 24–28px 宋体；月份 18–20px 宋体。**首页页头是例外**：站名 15px 宋体、状态句 11px mono，与 §4 一致——页头的大字位置留给观测条的读数，不留给站名。
- 动态正文 16px / 行高 1.7、**宋体**、最大 34rem。硬面板里唯一的长文是软的，这个反差是故意留的——它比任何装饰都更能说明「仪器测的是生活」。界面说明、批注、评论正文用无衬线。
- 亮暗两套各自验收：正文对比度 ≥ 7:1，标签与读数 ≥ 4.5:1（相对它所坐的那一层底，不是相对页面底）。

### 2.4 签名元素：主脊线

整个生活流由一条 1px 竖线贯穿——仪器的走线，同时也是时间轴。这是全站唯一的装饰性结构，别处一律安静。

```
┃
●   11.03 · 阴 · 南京西路        ← 节点色 = 内容类型的语义色
┃   今天去了城南那家旧书店，
┃   老板在收一整套旧地图。
┃
●   10.28 · 晴 · 家
┃   试着做了两次卤肉，第二次能吃。
```

- 脊线在桌面位于左栏左缘外 24px，手机距视口左缘 16px；节点 8px 圆点，落在线上。
- 节点颜色绑内容类型（见 §2.7），正文本身不着色。
- 脊线是一条**进度线**：它已描出的长度等于「你读到了这条时间线的哪里」，随滚动位置双向变化，回滚时收回去。它的数据源就是滚动位置，所以这不是装饰动画，是读数。实现用 `animation-timeline: scroll(root block)`，不依赖 JS。
- 两层分工写清楚：`--rule` 轨道**永远完整**（任何脚本状态、任何滚动位置都是整条），`--data` 填充表示进度，滚动到顶时为 0。关掉 JS 时轨道照样完整，页面结构不缺；不声称「填充也全显」——那与进度线的定义矛盾。
- 月份是脊线上的一个刻度：宋体标题 + mono 的条数读数 + 一条横跨左栏的 `--rule`，粘性停在顶部下方。v1 的邮戳全部删除。

### 2.5 第二元素：观测条

页面头部下方一整条，五个读数，`--rule` 分隔，mono 全大写标签 + 大读数。它是首页唯一的横幅，也是 `--data` 最大面积的使用处。

| 读数 | 源 | 无源时显示 |
| --- | --- | --- |
| 建站第 N 天 | `siteConfig.startedAt` 经 `daysSince()` | 不可能无源 |
| 动态 N 条 | 生活流数据源（阶段 2 之前就是本页渲染的那批内容） | `NOT AVAILABLE` |
| 本月 N 条 | 同上，按 `publishedAt` 计 | `NOT AVAILABLE` |
| 近 90 天提交 | `GET /api/github` 的 `days[]` 求和 | `NOT AVAILABLE` |
| 天气 | Open-Meteo，服务端取，缓存 5 分钟 | `NOT AVAILABLE` |

- 无源不许用 0、不许用 `—`、不许用占位数字。`NOT AVAILABLE` 本身是仪器可读的一部分，比一个假 0 诚实。
- **「服务器在线」这一格在拿到真实存活探测之前不显示**。`src/lib/uptime-server.ts` 算的是建站天数，不是存活；不许在面板上冒充心跳。
- 观测条不吸顶，滚动时跟着走。它的读数是服务端渲染的，客户端只做一次上翻。

### 2.6 动效

一条规矩：**没有数据源的不动**。

| 动 | 源 | 频率 | 阶段 |
| --- | --- | --- | --- |
| 本地时间走秒 | 站内时钟（北京时间） | 唯一常驻 | 1.5 |
| 脊线随滚动描出 / 收回 | 滚动位置 | 连续，双向 | 1.5 |
| 观测条数字上翻 | 各自读数 | 进场一次 | **2** |
| 90 天热图逐格点亮 | GitHub 事件序列 / 活动密度 | 按日期顺序，一次 | **2** |
| 读数闪一下 | 缓存刷新的时刻 | 有刷新才动 | 2 |
| 照片 hover 抬升 2px、边框转 `--data` | — | 仅 hover | 1.5 |

阶段 1.5 只交付脊线这一条有源动效；观测条数字上翻与热图逐格点亮留到阶段 2，等数据源与客户端接线稳定后再做。

- 无整页淡入，无常驻呼吸灯，无扫描线，无自定义鼠标，无全屏加载动画，无自动播放音频。
- 状态灯不呼吸。「在线」这件事由一个实心 `--ok` 点表达，静着。
- `prefers-reduced-motion: reduce` 下全部静态，脊线直接全显、数字直接落位。
- **不许复用 `src/components/site/reveal.tsx`**：它把 `opacity: 0` 写进产物 CSS，JS 一关内容永久消失。新的进场动效必须在「无脚本 / 脚本未执行」时内容可见（`@media (scripting: enabled)` 或根元素加 `.js` 类，二选一），实现前按 `node_modules/next/dist/docs/` 与当前 Tailwind 版本核对写法，不凭记忆。
- hover 抬升不再加深阴影（§2.2 禁用阴影分层），只改边框颜色。

### 2.7 内容形态（关键）

生活流**不能所有内容都装进同一种卡片**。三种形态保留，区分手段从「边框有无」改成**节点色 + 结构**：

| 形态 | 脊线节点 | 结构 | 何时用 |
| --- | --- | --- | --- |
| 纯文字短记 | `--muted-foreground` | 无边框无底，日期与地点一行 mono | 一两句话、心情、随想 |
| 图文 | `--data` | 图片块 + 1px `--rule` 边，图下 11px 批注 | 有照片时 |
| 读数卡 | 按类型：歌 `--ok`、书影音 `--wait`、引用/链接 `--data` | `--panel` 底 + 左上角类型标签（mono 全大写） | 歌、书影音、引用、链接 |

统一卡片会把一顿饭、一次旅行、一句话压成同一种声音。照片在暗底上会显灰，所以**照片永不降饱和度、不加滤镜、不加圆角投影**，只给 1px 边；觉得脏是报表模式该管的事。

## 4. 首页结构

首页就是观测台主屏。容器最大宽度 1152px（`max-w-6xl`），比 v1 放宽——仪器要横向铺读数。

### 桌面（≥ 1024px）

```
┌ 赵小元 · 在杭州，最近在学做饭 ─ 生活 书架 歌单 信箱 ─ ⌘K ─ 07:42:11 ┐
├──────────┬──────────┬──────────┬──────────┬─────────┤
│ 建站     │ 动态     │ 本月     │ 提交     │ 杭州     │
│ 128      │ 26       │ 6        │ 1,204    │ 17° 阴   │  ← 观测条
│ DAYS     │ MOMENTS  │ MONTH    │ 90D      │ METEO    │
├──────────┴──────────┴──────────┴──────────┴─────────┬┴────────┐
┃ 十一月 · 6 条                                        │ 此刻     │
┃                                                      │┌────────┐│
●  11.03 · 阴 · 南京西路                                 ││ 杭州   ││
┃  今天去了城南那家旧书店，老板在收一整套旧地图。          ││ 17° 阴 ││
┃      [ 照片 4:3 ]                                     │        │
┃                                                      │└────────┘│
●  10.28 · 晴 · 家                                      │ 在听     │
┃  试着做了两次卤肉，第二次能吃。                          │ ♪ 越难…  │
┃                                                      │ 手动 30  │
┃ 十月                                                 ├ 90 天 ──┤
┃  …                                                   │ ▁▂▅▇▃▂  │
└──────────────────────────────────────────────────────┴─────────┘
```

- 左栏 `minmax(0, 1fr)`，右栏固定 320px，`position: sticky`，顶部留 2rem。
- 脊线是左栏唯一的纵向结构（§2.4）；月份刻度粘性停在顶部下方。
- **页头的本地时钟是全站唯一走秒的地方**；右栏「此刻」不再重复放钟：天气、在听、在读、最近三条信箱留言、「写一封」。这一块是服务端组件，页面其余读数同样由服务端渲染。
- 在听 / 在读取自 `src/config/portfolio.ts` 里那份一直没人用的 `now`，**旁边必须标 `手动 · 更新于 10.30`**——它是站长自己填的，不许伪装成抓取。
- 「写一封」是描边按钮（`--data` 边 + `--data` 字），不做彩色填充底。

### 报表模式（亮）

版式与结构一模一样，只换 token 值。它的定位不是「给喜欢亮色的人」，而是**内容多照片、多截图时的可读模式**——同一块面板打印出来的样子。两套都是第一等公民。

页头的切换器文案用「观测台 / 报表」，不用「深色 / 浅色」：名字本身是设计的一部分，而且它解释了为什么存在第二种模式。

### 手机（< 768px）

- 单列。观测条是 **2 列网格**（`grid-cols-2`），五个读数依次排成 2+2+1；天气单独占第五格（第三行左半格），不并入「杭州」那一格。格间用 1px `--rule` 分隔（手机为横线、桌面为竖线）。
- 脊线距视口左缘 16px，正文左缘 40px（24px gutter），节点压在脊线上。
- 「此刻」折叠成首条动态之后的一条窄带，一行读数：`杭州 17° · ♪ 越难越爱`，点开展开完整面板。窄带高不超过 44px。
- 「写一封」按钮在可折叠的「此刻」面板内部，展开后才看得到；底部常驻链接推迟到阶段 3（留言墙上线时）再加，不做底部标签栏。
- 首屏必须至少看到两条动态（v1 这条验收不变）。

### 页头状态句

「在杭州，最近在学做饭」存在站点配置里，站长可在管理页改。它与站名同一行、同字号级，不用大字——页头的大字位置留给读数。

## 5. 各页结构

各页共用首页定的语言：页头一行读数、面板 + 1px `--rule`、语义色只绑状态。列表项一律用 `--rule` 分隔，不做卡片堆叠——堆卡片就又回到模板站了。

### 5.1 单条动态 `/life/[id]`

- 一条动态的放大读数：头部一行 mono 的日期 + 地点 + 天气，正文，照片；`MOOD / WEATHER / PLACE` 三个标签做成凹陷小格（`--panel-2` 底）。
- 下方是评论列表和评论框（需登录）。
- 上一页/下一页用「上一条 / 下一条」（v1 的「上一封 / 下一封」随信笺语言一起作废）。

### 5.2 书架 `/shelf`

三个标签：书 / 影 / 音。每个条目一行：封面缩略图（有就显示）、标题、作者或艺人、评分、一句短评、日期。

按时间倒序，不做分类筛选。

### 5.3 歌单 `/playlist`

- 「此刻循环」：最上面一首，大卡片。
- 「我的歌单」：按添加时间倒序，每行——曲名、艺人、一句推荐理由、平台图标。整行是外部链接，点击跳转网易云/QQ 音乐。
- 「大家推荐的」：访客推荐且已通过审核的歌，署名推荐人。
- 「推荐一首」按钮：登录后可填歌名、艺人、平台链接、一句推荐语。提交后状态为待审核，只有自己和站长可见。

### 5.4 信箱 `/letters`

- 网格化的留言面板：每条是一块 `--panel`，宽度吸附到 2 列或 3 列网格，不倾斜、不做纸条与拍立得质感。
- 每条头部一行读数：日期 + 昵称 + 状态灯（已通过 `--ok`、待审 `--wait`）；正文；可选的一首推荐歌。
- 首页露出最近三条。
- 表单需登录，提交后待审核。待审的那条本人可见，只有 `--wait` 一个标记，不写「请耐心等待审核」这类话。

### 5.5 笔记 `/notes`

保留的技术文章（10 篇），版式复用现有的 `.prose`（配色跟随两套模式）。RSS 保留。

v1 写明要「去掉点赞、浏览量等技术博客装饰」。在观测台语言里这两个是**合法读数**，不删：浏览量、阅读时长、点赞数以一行 mono 读数出现在标题下方，与「本月 N 条」同级同款式，不进正文行。装饰和读数的区别不在于有没有数字，在于数字有没有源、有没有含义——这两个都有。

### 5.6 项目 `/projects`

保留现有数据，改文案角度：不只列技术栈，补一句「为什么做」和「做完什么感受」。

### 6.3 渲染与缓存

- 首页、动态、书架、歌单、信箱都要读数据库，因此这些路由不再是纯静态。
- 写操作（发动态、审核、改「此刻」）后主动失效对应缓存标签，避免读的时候重算。
- 具体用 `use cache` / `cacheTag` / `revalidateTag` 中的哪一套，实现前按 `node_modules/next/dist/docs/` 的当前版本核对，不凭记忆写。
- 观测条的读数按新鲜度分两档缓存：日粒度（建站天数、条数、本月条数、90 天提交）按小时；天气按 5 分钟。
- 天气只走服务端：`GET` Open-Meteo（免 key、免注册），坐标与城市名存在站点配置里，客户端不直连、不采集访客位置（`Permissions-Policy: geolocation=()` 维持现状）。
- Open-Meteo 失败时缓存一个 60 秒的失败标记，读数格显示 `NOT AVAILABLE`，不做重试轰炸。
- 全站唯一的客户端常驻组件是页头的本地时钟（`useSyncExternalStore`，沿用 `runtime-info.tsx` 的做法，不在 effect 里 setState）；「此刻」面板与其余读数全部服务端渲染。

## 7. 认证与权限

### 7.1 邮箱验证码

1. 访客输入邮箱 → `POST /api/auth/email/request`
2. 生成 6 位数字码，存哈希，10 分钟有效
3. 通过 SMTP 发送（QQ 邮箱，已验证 465/587 从服务器可通）
4. 访客输入验证码 → `POST /api/auth/email/verify`
5. 邮箱不存在则创建 `visitor` 用户；存在则登录
6. 写入现有的签名会话 cookie

频率限制：同一邮箱 60 秒一次、每小时 5 次；同一 IP 每小时 20 次。

### 7.2 角色

- `owner`：站长，一个邮箱，由环境变量 `OWNER_EMAIL` 指定。可发布、审核、改状态句。
- `visitor`：可评论、留言、推荐歌。只能看到自己的待审核内容。

### 7.3 降级

SMTP 未配置时，登录功能整体关闭：评论、留言、推荐入口显示「暂未开放」，浏览不受影响。

## 8. 图片上传

- 客户端压缩：长边 2400px，输出 WebP，质量 0.82。
- 服务端二次校验：只接受 `image/webp` / `image/jpeg` / `image/png`，单张上限 2MB。
- 存储：容器挂载 volume `uploads:/app/uploads`，文件名用内容哈希，按 `YYYY/MM/` 分目录。
- 只有 `owner` 能上传（动态用）。访客留言不带头像和图片，避免滥用。
- 服务器当前剩余 16G；上线前清一次 Docker 构建缓存（约 7.7G）再评估。

## 11. 验收标准

**读数与诚实**

- 首页每一个读数都能指出它的源；指不出就不显示。
- 无源格显示 `NOT AVAILABLE`。全站不得出现假的 0、假的百分比、假的「实时」。
- 「在听 / 在读」旁边永远跟着「手动 · 更新于」字样。
- 「服务器在线」这类字样在接入真实存活探测之前不许出现。

**内容与结构**

- 手机首屏能看到至少两条动态，不需要滚动就知道「这个人在生活」。
- 所有互动入口在未登录时给出明确说明，而不是报错。
- 主导航与页脚不存在死链：要么有页面，要么不出现。阶段 1.5 必须处理当前五个死链（`/shelf`、`/playlist`、`/letters`、`/notes`、`/journal`）。

**视觉与可访问性**

- 两种模式下正文对比度 ≥ 7:1，标签与读数 ≥ 4.5:1（相对它自己坐的那一层底）。
- 关掉 JavaScript，首页正文与观测条读数完整可见（脊线可以是静态线）。
- `prefers-reduced-motion: reduce` 下没有任何持续动画，数字直接落位。
- 键盘可以完成：登录、发动态、评论、留言、审核。
- 所有读数使用 `tabular-nums`，走秒时版面不抖。
- 没有自动播放的音频；没有全屏加载动画；没有自定义鼠标；没有渐变与玻璃拟态；没有为装饰存在的 `01 / 02 / 03`。

**性能**

- 首页新增客户端 JS ≤ 30KB gzip（不含 React 与框架自身）。
- 折线、热图、脊线一律用 SVG 与 CSS，不引入 canvas 库，不引入 `three`。
- 天气与 GitHub 读数在服务端缓存，客户端不直连第三方。

## 12. 风险与取舍

| 风险 | 应对 |
| --- | --- |
| 暗底让照片和截图发灰、显脏 | 照片不加滤镜不降饱和，只给 1px 边；报表模式就是为它准备的；若某类内容在暗底始终不可读，改报表模式为默认 |
| 「仪器」显冷，不像一个人的家 | 宋体只给站名、月份和动态正文；状态句与正文语气保持日常；观测条封顶五个读数，不炫数据 |
| 阶段 2 前没有数据库，读数会不会假 | 观测条只显示能从「本页所读的那份内容」算出来的数；`moments` 表落地前，条数读数的语义就是「本站当前有这几条」 |
| Open-Meteo 挂了或访问不通 | 服务端缓存 + 60 秒失败标记 + `NOT AVAILABLE`；外部依赖不阻塞上线 |
| 动效变成新的模板味（黑底 + 荧光 + 扫描线） | §2.2 的语义色锁定和 §2.6 的「无源不动」是硬约束，评审逐条对 |
| 进场动效把内容藏起来（现有 `reveal.tsx` 的老毛病） | §11 要求关 JS 可读；实现不许复用 `reveal.tsx` |
| 2C2G 服务器扛不住 | 不在服务器上构建；读数走服务端缓存，客户端不直连第三方 |
| 动态是数据库渲染，首页不再是静态页，读取变慢 | 写后失效 + 读时缓存；上线后看首字节时间 |
| 邮箱验证码依赖第三方 SMTP，可能进垃圾箱 | 用 QQ 邮箱授权码，发信人固定；文案里提示检查垃圾箱 |
| 图片存本地，服务器磁盘会涨 | 客户端压缩 + 内容哈希去重 + 定期检查容量 |
| 访客推荐会变成广告位 | 默认待审核；同一用户每天最多 3 条 |
| 从 30 篇压到 10 篇，可能有外部链接失效 | 归档的文章保留文件，加 301 到 `/notes` 的兜底 |
