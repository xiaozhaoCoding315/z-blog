# 个人空间改版 · 设计文档

日期：2026-11-07
状态：待评审

## 1. 目标与非目标

### 目标

把一个以技术文章为主轴的博客，改造成以「生活流」为主轴的**个人空间**：

- 访客打开首页，先看到这个人最近在过什么生活，而不是最新一篇技术文章。
- 发布压力要低——一两句话加一张照片就能发一条。
- 访客能参与：评论、在信箱留言、推荐歌。
- 视觉要有辨识度，且不像模板站或 AI 生成。

### 非目标

- 不做社交网络。没有关注、私信、转发、点赞排行。
- 不做多用户内容平台。访客只能评论和留言，不能发帖。
- 不做音频托管。歌单只做卡片 + 跳转外部音乐平台。
- 不做实时通知、推送。

### 一句话定位

> 赵小元的个人空间：记录生活，收信，听歌，看书。

## 2. 视觉系统：信笺与邮戳

### 2.1 取材

两个真实物件：**80g 道林信纸**、**邮局日戳**。

不采用「复古滤镜」「做旧纸张纹理」这类处理——材质感来自排版和形状，不来自噪点贴图。

### 2.2 颜色

| Token | 亮色 | 暗色 | 用途 |
| --- | --- | --- | --- |
| `--paper` | `#f4f4ef` | `#17181a` | 页面底 |
| `--paper-raised` | `#fbfbf7` | `#1e1f22` | 单张信笺（卡片） |
| `--ink` | `#1a1b18` | `#e6e6df` | 正文 |
| `--ink-soft` | `#6b6e67` | `#9a9d96` | 批注、时间、次要信息 |
| `--stamp` | `#2f4f74` | `#8fb0d6` | 邮戳蓝，全站主色 |
| `--postmark` | `#a83f30` | `#d9776a` | 朱红，只用于日期章和未读 |
| `--rule` | `#dcdcd3` | `#2c2d31` | 格线、分隔线 |

约束：

- `--postmark` 在全站出现的位置不超过三类：邮戳日期章、未读标记、必要的错误强调。不做按钮底色。
- 不使用渐变、玻璃拟态、彩色投影。
- 不改用暖米色 + 陶土橙的组合——那是当前最典型的 AI 设计特征。

### 2.3 字体

| 角色 | 字体 | 说明 |
| --- | --- | --- |
| 标题 / 站名 / 月份 | 思源宋体（Noto Serif SC） | 信笺的抬头，沿用现有字体 |
| 正文 | 思源黑体 + 系统无衬线 | |
| 日期、元信息、批注 | Geist Mono / 等宽 | 像打字机敲上去的日期 |
| 手写体 | **不使用** | 中文字体包体积大，且「手写体点缀」是最常见的滥用套路 |

字号：

- 站名 28–32px
- 月份 20–22px
- 动态正文 16px / 行高 1.85
- 日期章 11px 等宽
- 批注 12px

### 2.4 签名元素：邮戳

结构：

```
   ╭─────────────╮
  │   ·  11.03 ·  │   ← 1.5px 描边圆，直径 88–112px
  │  南 京 西 路   │   ← 一行 4–6 字的地点或天气
   ╰─────────────╯
         ZXY       ← 小字，刻在圆内下沿
```

规则：

- 圆内那行字随场景变：动态里是地点或天气，信箱里是留言人的昵称，月份分隔处是月份名。
- 整体旋转 -8° 到 -12°，角度随位置略有差异，但同一屏内不超过两档。
- **只出现在四处**：动态的日期、信箱的每条留言、月份分隔、404 页。
- 导航、按钮、卡片标题、页脚一律不用。签名一旦到处都是就不再是签名。

实现：一个 `<Postmark>` 组件，参数 `date`、`place`、`size`、`rotate`。纯 CSS + 文本，不用图片。

### 2.5 第二签名：齿孔

照片和纸条的上/下边缘做 6px 圆孔，用 CSS `mask-image` 的 `repeating-radial-gradient` 实现，不引入图片资源。

只用在这两处：动态里的照片、信箱里的纸条。不做胶带贴纸、不做胶卷齿孔边框。

### 2.6 内容形态（关键）

生活流**不能所有内容都装进同一种卡片**。强制三种形态：

| 形态 | 结构 | 何时用 |
| --- | --- | --- |
| 纯文字短记 | 左栏一半宽，无边框，日期章在左上 | 一两句话、心情、随想 |
| 图文 | 满幅或两图并排，带齿孔，图下 12px 批注 | 有照片时 |
| 卡片 | 有边框和浅底，左上角类型标记 | 歌单、书影音、引用、链接 |

统一卡片会把一顿饭、一次旅行、一句话压成同一种声音。

### 2.7 动效

- 只有照片在 hover 时抬升 2px 并加深阴影，其余元素不动。
- 页面切换不做整页淡入。
- 遵守 `prefers-reduced-motion`。
- 不自动播放音频。

```

/shelf         书架：书 / 影 / 音

/notes/[slug]  单篇笔记
/projects      项目
/journal       日志
/friends       友链
/about         关于
```

导航：

- 主导航四项：**生活 · 书架 · 歌单 · 信箱**
- 页脚：笔记 · 项目 · 日志 · 友链 · 关于
- 头像菜单：登录/登出、我的推荐、管理入口（仅站长可见）

删除：`/interview` 全部路由与 API（数据表暂时保留，不删除数据）。

## 4. 首页结构

### 桌面（≥ 1024px）

```
┌──────────────────────────────────────────────┐
│ 赵小元                       生活 书架 歌单 信箱 │
│ 在杭州，最近在学做饭                             │
├───────────────────────────┬──────────────────┤
│                           │  ◎ 此刻           │
│  十一月 ⌒                  │  ┌────────────┐  │
│                           │  │ 正在听      │  │
│  ◯ 11.03                  │  │ 专辑封面    │  │
│  今天去了城南那家旧书店…    │  │ 曲名 / 艺人 │  │
│  ┌──────────────┐         │  └────────────┘  │
│  │              │         │  ┌────────────┐  │
│  └──────────────┘         │  │ 在读 / 在看 │  │
│                           │  └────────────┘  │
│  ◯ 10.28                  │  ┌────────────┐  │
│  ……                       │  │ 最近的信    │  │
│                           │  └────────────┘  │
│                           │  [ 写一封 ]      │
└───────────────────────────┴──────────────────┘
```

- 左栏八栏，右栏四栏，右栏 `position: sticky`。
- 月份做粘性分隔条，滚动时停在顶部下方。
- 右栏「此刻」三块：正在听（歌单里标记为「此刻」的一首）、在读/在看（书架里标记的一项）、最近三条信箱留言。
- 右栏底部固定「写一封」按钮。

### 手机（< 768px）

- 单列，最大宽度 680px。
- 「此刻」折叠成首条动态之后的一张横向卡，高度不超过 120px。
- 底部只有一条「写一封」的常驻链接，不做底部标签栏。

### 页头状态句

「在杭州，最近在学做饭」这句话存在站点配置里，站长可在管理页改。它是首页唯一的「自我介绍」。

## 5. 各页结构

### 5.1 单条动态 `/life/[id]`

- 一条完整的信笺：日期章、正文、照片、地点/天气/心情标签。
- 下方是评论列表和评论框（需登录）。
- 上一页/下一页用「上一封 / 下一封」。

### 5.2 书架 `/shelf`

三个标签：书 / 影 / 音。每个条目一行：封面缩略图（有就显示）、标题、作者或艺人、评分、一句短评、日期。

按时间倒序，不做分类筛选。

### 5.3 歌单 `/playlist`

- 「此刻循环」：最上面一首，大卡片。
- 「我的歌单」：按添加时间倒序，每行——曲名、艺人、一句推荐理由、平台图标。整行是外部链接，点击跳转网易云/QQ 音乐。
- 「大家推荐的」：访客推荐且已通过审核的歌，署名推荐人。
- 「推荐一首」按钮：登录后可填歌名、艺人、平台链接、一句推荐语。提交后状态为待审核，只有自己和站长可见。

### 5.4 信箱 `/letters`

- 墙面式排布，纸条 / 拍立得混排，尺寸不一但吸附到网格。
- 每条：邮戳（日期 + 昵称）、留言正文、可选的一首推荐歌。
- 首页露出最近三条。
- 表单需登录，提交后待审核。

### 5.5 笔记 `/notes`

保留的技术文章（10 篇），版式复用现有的 `.prose`，但去掉文章页的点赞、浏览量等「技术博客」装饰。RSS 保留。

### 5.6 项目 `/projects`

保留现有数据，改文案角度：不只列技术栈，补一句「为什么做」和「做完什么感受」。

### 6.3 渲染与缓存

- 首页、动态、书架、歌单、信箱都要读数据库，因此这些路由不再是纯静态。
- 写操作（发动态、审核、改「此刻」）后主动失效对应缓存标签，避免读的时候重算。
- 具体用 `use cache` / `cacheTag` / `revalidateTag` 中的哪一套，实现前按 `node_modules/next/dist/docs/` 的当前版本核对，不凭记忆写。

## 7. 认证与权限

### 7.1 邮箱验证码

1. 访客输入邮箱 → `POST /api/auth/email/request`
2. 生成 6 位数字码，存哈希，10 分钟有效
3. 通过 SMTP 发送（QQ 邮箱，已验证 465/587 从服务器可通）
4. 访客输入验证码 → `POST /api/auth/email/verify`
5. 邮箱不存在则创建 `visitor` 用户；存在则登录
6. 写入现有的签名会话 cookie

频率限制：同一邮箱 60 秒一次、每小时 5 次；同一 IP 每小时 20 次。

### 7.2 角色

- `owner`：站长，一个邮箱，由环境变量 `OWNER_EMAIL` 指定。可发布、审核、改状态句。
- `visitor`：可评论、留言、推荐歌。只能看到自己的待审核内容。

### 7.3 降级

SMTP 未配置时，登录功能整体关闭：评论、留言、推荐入口显示「暂未开放」，浏览不受影响。

## 8. 图片上传

- 客户端压缩：长边 2400px，输出 WebP，质量 0.82。
- 服务端二次校验：只接受 `image/webp` / `image/jpeg` / `image/png`，单张上限 2MB。
- 存储：容器挂载 volume `uploads:/app/uploads`，文件名用内容哈希，按 `YYYY/MM/` 分目录。
- 只有 `owner` 能上传（动态用）。访客留言不带头像和图片，避免滥用。
- 服务器当前剩余 16G；上线前清一次 Docker 构建缓存（约 7.7G）再评估。

| 阶段 | 内容 | 完成标志 |

每阶段结束都要：`npm run type-check`、`npm run lint`、`node scripts/check-content.mjs`、`npm run build`，并在亮暗两个主题下截图验收。

## 11. 验收标准

- 首页首屏在手机上能看到至少两条动态，不需要滚动才能看到「这个人在生活」。
- 亮色和暗色下，正文对比度不低于 7:1，次要文字不低于 4.5:1。
- 所有互动入口在未登录时给出明确说明，而不是报错。
- 键盘可以完成：登录、发动态、评论、留言、审核。
- 没有自动播放的音频；没有全屏加载动画；没有自定义鼠标。
- 全站没有一处为了装饰而存在的 `01 / 02 / 03`。

## 12. 风险与取舍

| 风险 | 应对 |
| --- | --- |
| 动态是数据库渲染，首页不再是静态页，读取变慢 | 写后失效 + 读时缓存；上线后看首字节时间 |
| 邮箱验证码依赖第三方 SMTP，可能进垃圾箱 | 用 QQ 邮箱授权码，发信人固定；文案里提示检查垃圾箱 |
| 图片存本地，服务器磁盘会涨 | 客户端压缩 + 内容哈希去重 + 定期检查容量 |
| 访客推荐会变成广告位 | 默认待审核；同一用户每天最多 3 条 |
| 从 30 篇压到 10 篇，可能有外部链接失效 | 归档的文章保留文件，加 301 到 `/notes` 的兜底 |
