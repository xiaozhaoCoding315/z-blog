question: GC 日志怎么读？从日志里能看出什么问题？
category: JVM

先认格式（G1 一行 Young GC 长这样）：

```
[GC pause (G1 Evacuation Pause) (young)  128M->36M(512M)  15ms]
```

**一眼三信息**：GC 前堆用 128M → GC 后 36M（**回收了 92M，干活了**）/ 总堆 512M / 本次停了 15ms。

**看什么病**：

**1. Young GC 频率**：日志时间戳一分钟刷几十条——新生代太小或对象存活率异常（大对象分配进 Eden 就走）。健康参考：几秒到十几秒一次、单次低于 50ms

**2. GC 后堆不降**：`512M->480M` 每次只回收一点点——**对象都活着**：要么真业务缓存大，要么泄漏——dump 看支配树

**3. Full GC 出现**（G1 里是 to-space exhausted / Humongous 分配失败）：大对象太多（G1 里超过半个 Region 的对象走特殊通道，大量分配触发并发失败）——排查"一次性 new 大集合/大数组"的代码

**4. 单次停顿超目标**：MaxGCPauseMillis 设 100 实际 300——Region 数太多或引用更新慢，参考调整 RegionSize/并发线程数

**工具**：GCEasy / GCViewer 把日志拖进去出图表——趋势比单行重要。**答题带一句"我上线必开 GC 日志，出问题先看趋势再动手"就是老手味**。
