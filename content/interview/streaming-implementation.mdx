question: LLM 流式输出是怎么实现的？SSE 和 WebSocket 怎么选？

**为什么必须流式**：完整生成要 10 秒+，用户盯空白页必流失；流式把**首字时间压进 1 秒**——从"卡死"变"正在打字"。

**全链路**：LLM API 以 SSE 逐 chunk 吐字 → 服务端**逐 chunk 转发**（别攒齐！）→ 浏览器 fetch ReadableStream 逐块读、增量渲染。

**SSE vs WebSocket**：SSE 单向下行、跑在 HTTP 上、**自带断线重连**——LLM 对话的天选协议（ChatGPT、本站都用）；WebSocket 双向二进制、要握手升级+心跳——语音对话、协同编辑才需要。

**前端三个坑**：EventSource 不支持 POST/自定义头（用 fetch 手撸解析）；逐字 setState 卡顿（rAF 批量追加）；流中半截 Markdown 要容错（代码块没闭合）。

**后端两个坑**：Nginx 默认缓冲——加 `X-Accel-Buffering: no` 否则流式失效；要区分正常结束与中断信号。
