---
question: 谈谈 Java 异常体系？受检异常和非受检异常怎么选？
category: Java 基础
difficulty: 易
tags: [异常]
---
**先画树**：Throwable 是老祖宗，两大分支——Error 和 Exception。

- **Error**：JVM 自己出问题了（内存爆了 OOM、栈溢出），你捕获也没用，让它死
- **Exception** 里又分两支：
  - **受检异常**（IOException 这种）：编译器强制你 try-catch 或 throws，不处理编译不过。语义是"这种错是可预期的，你必须表态怎么办"
  - **非受检异常**（RuntimeException，比如空指针、数组越界）：编译器不管，语义是"这是你代码写错了，改代码去，别用 try 兜"

**实际项目怎么选**：业务异常（余额不足、库存不够）推荐自定义 `BusinessException extends RuntimeException`——不强制每一层方法签名都 throws，全局异常处理器统一接住返回错误码。这是阿里规约推荐的做法，答出来很加分。

**finally 的坑**：finally 里写 return 会把 try 里的返回值和异常都吞掉——所以 finally 只该做清理。资源关闭优先 try-with-resources，自动调用 close 还不会漏。
