**先泼冷水**：多 Agent 不是越多越好——上下文在 Agent 间传递会失真，协调成本指数上升。**单 Agent + 好工具能解决的别上多 Agent**。

**需要多 Agent 的信号**：上下文窗口装不下（任务跨度大）、需要**独立视角**（评审员/辩手对抗）、职责需要隔离权限（执行者 vs 审批者）。

**三种经典模式**：
1. **流水线（编排者-工人）**：Planner 拆任务 → Worker 执行 → Aggregator 汇总——最稳定，主流
2. **对抗制衡**：执行者 + 只读 Reviewer（pass/warn/block）——用权限隔离换质量
3. **群体讨论**：多角色辩论投票——创意类有效，工程类低效难控

**工程要点**：消息协议结构化、共享黑板（Blackboard）还是点对点、失败超时处理、全程轨迹可回放审计。
