question: 多 Agent 协作有哪些模式？什么时候需要多 Agent？

**先泼冷水（这句最值钱）**：多 Agent 不是越多越强——上下文在 Agent 间传递会失真，协调成本指数涨。**单 Agent + 好工具能解决的，别上多 Agent**。

**三个"该上"的信号**：任务大到上下文装不下（研究+编码+测试各需大量上下文）；需要**独立视角对抗**（执行者+评审员）；需要**权限隔离**（干活的不能自己批自己的钱）。

**三种编排**：

1. **流水线（主流）**：Planner 拆任务 → Worker 各干一段 → Aggregator 汇总。像装修队：设计师出图、水电木瓦油各干各的、工头验收
2. **对抗制衡**：Executor 提案 + **只读 Reviewer**（只有 pass/warn/block 三个按钮，零写权限）——用权限隔离换质量，代码评审场景极佳
3. **群体讨论**：多角色辩论投票——创意类有效，工程类低效难控

**工程四件套**：消息结构化（别传自然语言长文）、失败与超时处理、全程轨迹可回放、每个 Agent 的 token 成本核算。
