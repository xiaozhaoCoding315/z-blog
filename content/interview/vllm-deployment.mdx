**从"能跑"到"能扛"的三个台阶**：

**1. 推理引擎——vLLM 为什么是标配**：朴素推理（HuggingFace transformers）一次处理一个请求，GPU 大量算力在闲着。vLLM 的 **PagedAttention**（显存像操作系统管理内存一样分页管理 KV 缓存）+ **Continuous Batching**（请求动态凑批，完成一个立刻补位）——**吞吐 10~20 倍提升**，还提供 OpenAI 兼容 API（业务代码零改动切换）。同类：SGLang（更快的前缀缓存）、TensorRT-LLM（NVIDIA 官方）。

**2. 量化——塞进更小的卡**：FP16 的 70B 模型要 140GB 显存（两张 A100）。量化 = **把权重从 16 位压到 4/8 位**（GPTQ/AWQ 算法），显存砍 4 倍、精度损失个位数百分比——**70B 塞进单张 A100、7B 跑在消费级显卡**是常态操作。

**3. 服务化配套**：多副本负载均衡（Nginx/LB 分发 OpenAI 格式请求）；显存不够 OOM 的监控告警；**流式输出的网关配置**（SSE 不缓冲）；按 QPS 弹性扩容。

**选型速查**：7B~14B（单卡 24G，量化后更宽裕）做轻任务；70B 级别质量敏感场景；** API 调用 vs 自部署的分界**——数据合规要求 / 调用量大到 API 账单超过 GPU 租金（大约月 5 万人民币量级）才值得自部署。

**一句话**："vLLM 管**跑得快**，量化管**塞得下**，服务化管**扛得住**——自部署 LLM 的三件套"。
