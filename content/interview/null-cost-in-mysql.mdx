---
question: MySQL 字段允许 NULL 有什么代价？为什么不建议默认 NULL？
category: MySQL
difficulty: 中
tags: ["NULL", 规范]
---
**四个实打实的代价**：

1. **索引统计变复杂**：NULL 值也进索引，但优化器对 NULL 列的统计和选择率判断更容易失误
2. **比较语义陷阱**：`WHERE col != 'x'` **查不出 NULL 行**（NULL 和任何值比较结果是 UNKNOWN）——"不等于 x"直觉上该包含"没填"的，实际漏了。要 `OR col IS NULL` 补
3. **count(col) 不数 NULL**：统计口径悄悄偏差
4. **NOT IN 陷阱之王**：`col NOT IN (1,2,NULL)` **永远查不出任何行**——子查询里混进一个 NULL，整条 SQL 静默返回空集，**不报错**——线上事故级坑

**规范做法**：**NOT NULL + 默认值**——数字给 0、字符串给 ''、状态给具体枚举；"真的没填"用魔法值（如 -1）或单独标记字段表达。

**反方观点也听一句**（显得客观）：NULL 语义上是"未知"，默认值语义是"已填了某个值"——两者业务含义不同，强扭默认值可能污染统计。**结论：能 NOT NULL 就 NOT NULL，必须可空时在代码层显式处理 IS NULL 逻辑，绝不隐式依赖**。
