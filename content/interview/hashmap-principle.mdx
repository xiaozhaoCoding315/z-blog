question: HashMap 的底层实现原理是什么？JDK 1.8 做了哪些优化？

**JDK 1.8 的 HashMap = 数组 + 链表 + 红黑树。**

- **put 流程**：对 key 的 hashCode 做扰动（高 16 位异或低 16 位）→ 与 `(n-1)` 位运算定位桶 → 桶为空直接放入；不为空则链表尾插或命中红黑树；链表长度 ≥ 8 且数组长度 ≥ 64 时树化。
- **扩容**：负载因子默认 0.75，元素超过 `容量 × 0.75` 时 2 倍扩容；1.8 优化为**高低位拆分**——节点 hash 与 oldCap 按位与为 0 留原位，非 0 移到「原下标 + oldCap」，避免了重新计算 hash。
- **为什么容量是 2 的幂**：`hash & (n-1)` 等价于取模但更快，且扩容拆分时只需判断一位。

**1.8 相对 1.7 的优化**：尾插替代头插（解决扩容死循环）、引入红黑树（链表过长时查询从 O(n) 降到 O(log n)）、扩容高低位拆分。
