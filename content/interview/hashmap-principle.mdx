这题基本是 Java 面试的"开胃菜"，面试官想看你是真理解，还是只会背"数组加链表"六个字。

**先用大白话讲清楚**：把 HashMap 想象成一排储物柜。你存东西时，它拿 key 算出一个编号（哈希值），把东西塞进对应编号的柜子；取的时候再算一次编号，直奔那个柜子——不用挨个翻，所以快。

**那两个 key 算出同一个编号怎么办？**（面试官必追问）这叫哈希冲突。1.8 的做法是：冲突的 entry 在同一个柜子里排成一条链表；要是这条队排到 8 个人以上（且数组够大），就升级成红黑树——从"挨个问一遍"变成"折半找"，队列再长也不怕。

**举个例子感受下**：存 100 万个用户，用 ArrayList 查某个用户平均要翻 50 万次；HashMap 算一次哈希直接定位。这就是 O(n) 和 O(1) 的差距。

**1.8 相比 1.7 的三个优化**（背这三条就够）：

1. **头插改尾插**——1.7 扩容时头插法在多线程下会形成环形链表，一 get 就死循环 CPU 飙满；尾插堵了这个洞（但 HashMap 依然线程不安全，并发要用 ConcurrentHashMap）
2. **引入红黑树**——链表太长时查询从 O(n) 降到 O(logn)
3. **扩容时高低位拆分**——1.7 扩容要重新算每个人的哈希；1.8 发现"哈希对上旧容量做位与"就知道你该留原地还是搬到"原编号+旧容量"的位置，省掉重算

**一个小细节加分**：容量永远是 2 的幂，因为 `hash & (n-1)` 和取模效果一样但快得多。
