**直传 2GB 文件的死法**：HTTP 超时重传从头来（网络抖一下前功尽弃）、网关有 body 大小限制、中途断了用户骂娘。

**分片上传三步走**：

1. **前端切片**：按 5MB 切成 400 片，**并发上传**（3~5 并发，失败单片重传——爆炸半径从 2GB 缩到 5MB）
2. **合并**：全部片到位后通知服务端按序合并（或服务端边收边追加写入）
3. **秒传与续传的魔法——文件指纹（hash）**：
   - **秒传**：上传前先算整个文件的 MD5 问服务端"有没有这个指纹的文件"——有（别人传过相同文件）**直接标记成功，一个字节都不传**
   - **断点续传**：上传前问"这个文件的 1~137 片你们已经有了吗"——服务端返回已收片清单，**只传缺的 138~400 片**

**实现细节三件**：指纹计算用 Web Worker 算（别卡 UI）；分片记录 Redis（key=文件hash，value=已收片号集合，带过期）；**合并的原子性**（防止重复触发合并——Redis setnx 锁）。

**对象存储加速**：直接对接 OSS/COS 的**分片上传 API**（前端拿临时凭证直传云存储，服务端只发凭证不经手流量——服务器带宽成本骤降）。

**一句话**："大文件上传 = **切片缩爆炸半径 + hash 指纹实现秒传续传 + 优先直传对象存储**"。
