---
question: count(*)、count(1)、count(字段) 哪个快？为什么千万级表 count 要十几秒？
category: MySQL
difficulty: 中
tags: [count, 优化]
companies: [美团]
---
**先破除一个流传甚广的谣言**："count(列) 比 count(*) 快"——**假的**。真相：count(*) ≈ count(1) 最优，MySQL 对 count(*) 有专门优化（ server 层直接数行，不取值）；count(字段) 要判断每行的字段是否为 NULL（不为 NULL 才数），**反而最慢**，还语义不同（少数 NULL 行）。

**为什么千万级 count 这么慢**：count 要"知道有多少行"——InnoDB 是 MVCC 多版本，**不同事务看到的行数不一样**，没法像 MyISAM 那样存个总行数直接读（MyISAM 无事务所以能存），只能真的扫一遍（挑最小的索引数）。

**怎么治**：

1. **不许精确就别精确**：`EXPLAIN` 的 rows 估算值、或"约 10 万条"展示
2. **计数表**：触发器/业务代码把 count 增量维护在一张小表/Redis 里——写时多一步，读时 O(1)
3. **分页总数也同理**：前端只显示"下一页"不给总页数（信息流的做法）——**消灭需求是最好的优化**

**点睛**："count 慢不是 SQL 写错，是 MVCC 的代价；优化方向是'还要不要精确总数'这个产品问题"。
