---
question: 如何保证消息不丢失、不重复消费？
category: 消息队列
difficulty: 中
tags: [MQ, 可靠性]
companies: [阿里, 美团]
---
**消息不丢失（三段论）**：
1. **生产端**：发送确认机制（ack/confirm），失败重试 + 本地消息表兜底
2. **Broker**：同步刷盘 + 主从复制（RocketChat 同步复制 / Kafka acks=all + min.insync.replicas≥2）
3. **消费端**：手动 ACK，业务处理成功后才确认；失败重回队列/死信队列

**不重复消费**：网络重试必然导致「至少一次」投递，重复无法根除，**只能在消费端幂等**：
- 唯一业务 ID + 数据库唯一索引
- Redis SETNX 记录已处理的消息 ID
- 状态机（只允许待支付→已支付单向流转）

**顺序性**（追问常客）：单分区内有序——按业务 key hash 到同一队列/分区，消费端单线程处理该分区。
