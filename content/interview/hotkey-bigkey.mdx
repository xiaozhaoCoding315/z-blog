---
question: 什么是热 key、大 key？分别有什么危害和处理办法？
category: Redis
difficulty: 中
tags: [热key, 大key]
companies: [美团, 字节]
---
**热 key**：流量全砸在一个 key 上。比如某明星官宣，他的资料 key 一秒 50 万次读——**集群再大也没用**，因为一个 key 只能待在一个节点上，单台 CPU/带宽被打爆。扩容救不了热 key——这是它和一般性能问题的本质区别。

**热 key 解法三板斧**：
1. **本地缓存兜底**（最有效）：应用服务器内存里缓存这份热数据（Caffeine，短 TTL + 定时刷新），读请求根本不打 Redis
2. **key 打散**：把 `hot_data` 复制成 `hot_data_1` ~ `hot_data_10`，读的时候随机挑一个——流量摊到多节点
3. 发现手段：`redis-cli --hotkeys`、客户端采样上报

**大 key**：单个 value 大得离谱（String 超过 10KB、集合元素上万）。危害很具体：**Redis 单线程**，删一个百万元素的集合要卡主线程几秒——这几秒里**所有请求都排队**，看着像宕机；主从同步也会被它拖出延迟。

**大 key 解法**：拆（大 hash 按 user 拆成 N 个小 hash）、压缩、能放对象存储就别塞 Redis；删除用 **UNLINK**（异步后台删）不用 DEL；4.0+ 开 lazy-free。

**点睛句**："热 key 治流量倾斜，大 key 治单点卡顿——都是'单节点扛不住'的病，病因不同"。
