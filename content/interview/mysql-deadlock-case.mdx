---
question: 举一个 MySQL 死锁的例子？怎么避免？
category: MySQL
difficulty: 难
tags: [锁, 死锁]

---
**先讲一个一秒听懂的案例**：表里有 10 万行，你执行 `UPDATE orders SET status=1 WHERE remark='急'`，而 remark 上**没索引**——InnoDB 的行锁是挂在索引上的，走不了索引就退化为**锁住全部记录**。两个这样的 UPDATE 同时来，互相等对方放锁——死锁。

**另一个高频案例**：两个事务同时 INSERT 同一个唯一键——一个成功，另一个报重复键错误后转成 UPDATE（要加锁），和对方的 INSERT 间隙锁互相卡住。

**怎么避免（按实用度排）**：
1. **更新条件必须命中索引**——把锁范围从全表缩到几行，这一条就消灭大半死锁
2. **多个更新的顺序保持一致**：都按 id 升序处理（`ORDER BY id` 再逐条更新），等待图成不了环
3. 事务短小：事务里别调外部接口、别等用户输入
4. 缩小 innodb_lock_wait_timeout，让等死锁的早点失败 + 业务层重试——**被回滚的那个事务重试是安全的**（InnoDB 检测到环会主动回滚一方）

**怎么查现场**：`SHOW ENGINE INNODB STATUS` 拉到最底，LATEST DETECTED DEADLOCK 段画着两个事务各持什么等什么，一目了然。

**答题亮点**：结尾带一句"死锁不可怕，InnoDB 有检测机制；可怕的是锁范围被无索引条件放大导致的性能雪崩"。
