question: 怎么把 MySQL 的变更实时同步到 Redis/ES？（Canal 原理）

tags: [数据同步, Canal]

**需求场景**：数据库是真相源，但 Redis 缓存/ES 搜索索引要跟着变——**怎么不多写一份代码就自动同步？**

**Canal 的思路——"伪装成 MySQL 的从库"**：

1. Canal 服务器**把自己伪装成一个 MySQL slave**，向主库发起 binlog dump 请求
2. MySQL 毫无察觉地把 binlog 流推给它（就像推给真从库）
3. Canal **解析 binlog**（哪张表哪行 INSERT/UPDATE/DELETE，前像后像都有）投递给下游（MQ/客户端）
4. 消费端拿到变更事件：**更新 Redis 对应 key、刷新 ES 文档**——异构数据自动保持同步

**对比双写（业务代码里又写 DB 又写 MQ）的碾压优势**：业务零侵入（不用改一行代码）；**不丢**（binlog 是数据库确认落盘的事实，比"业务发消息可能失败"可靠）；顺序天然保证（binlog 有序）。

**实战架构**：Canal → Kafka（缓冲/削峰/多订阅）→ 各下游消费者。**消费侧要点**：幂等（binlog 重放）、**全量+增量衔接**（首次上线先全量灌一遍，再从固定位点追增量）。

**同类应用**：缓存失效（本站删缓存方案的升级版）、ES 同步、审计日志、跨机房同步——**"订阅数据变更"是个通用模式**。
