**常见选项**：

| 方案 | 适用 |
| --- | --- |
| **pgvector** | 已有 PostgreSQL、千万级以下向量、想要事务/Join/与业务数据同库 |
| Milvus/Qdrant | 亿级向量、高 QPS、需要分布式 |
| ES 8.x | 已有 ES，想混合关键词+向量 |
| FAISS | 单机实验、嵌入库自管 |

**pgvector 的优势**：向量与业务表同库——过滤（按 user/分类/时间）直接走 SQL where，一致性强，运维零新增；HNSW 索引百万级毫秒响应（本站 28 个分块用它绰绰有余）。

**选型口径**：数据量低于千万且过滤条件复杂 → pgvector；超大规模或需要多租户隔离 → 专用向量库；别为「看起来专业」引入新组件——**能用现有设施解决就不要加运维负担**。
