question: Redis 的过期删除策略和内存淘汰策略？

**两个问题别混**：过期删除管"已设置 TTL 且到期的 key"；内存淘汰管"内存满了，踢谁出去"。

**过期删除 = 惰性 + 定期，双管齐下**：

- **惰性删除**：key 到期了先不动它，等**有人来访问时**一看过期了才删——省 CPU 但冷数据会占着内存
- **定期删除**：弥补惰性的漏洞。Redis 每 100ms 随机抽 20 个带 TTL 的 key，过期的删掉；**如果这批过期比例超 25%，立刻再抽一批**（循环有上限，防止卡住主线程）——像物业抽查楼道杂物

**内存淘汰（maxmemory 满了踢谁）**，记住三个实用的：
- noeviction：默认，内存满后写命令直接报错（缓存场景千万别用默认！）
- **allkeys-lfu**：全量 key 里踢"访问频率最低"的——**缓存场景最推荐**（LFU 比 LRU 抗"偶发扫描"——一个冷 key 偶然被扫到一次，LRU 会误以为它热，LFU 记频率不会被骗）
- volatile-lru：只踢设了 TTL 的（适合 Redis 里同时放缓存和持久数据的场景）

**实践口径**：纯缓存场景 `maxmemory` 设物理内存 60% + allkeys-lfu，一句话说完。
