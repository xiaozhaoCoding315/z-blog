**CAP**：分布式系统在网络分区（P 必然存在）时，一致性 C 与可用性 A 只能二选一。注意：**没有网络分区时 C 和 A 可以兼得**——所以本质是"分区时的取舍"。

- CP：ZooKeeper、etcd（选举期间不可用）
- AP：Eureka（对等复制，容忍脏读）、Redis Cluster

**BASE**：AP 的延伸——基本可用（降级/限流）、软状态（允许中间态）、最终一致（补偿/对账收敛）。

**实践话术**：互联网业务大多选 AP + 最终一致（订单/T+1 对账），资金相关局部选 CP（转账的扣款环节）。别背理论，说"我们系统哪里 C 哪里 A"。
