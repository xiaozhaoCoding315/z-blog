---
question: 怎么保证 LLM 稳定输出合法 JSON？
category: Agent / LLM 应用
difficulty: 中
tags: [结构化输出, JSON]
companies: [字节]
---
**为什么难**：LLM 本质在"续写文本"——它真心觉得自己输出了 JSON，但多了句"好的，以下是结果："、少个右括号、字符串里冒出裸换行——**解析器当场去世**。靠 prompt 里写"必须输出JSON"是不够的。

**四层防御，层层加码**：

**1. API 层（最硬的保证）**：OpenAI/智谱的 **JSON mode / response_format**——约束解码阶段只在合法 JSON token 里采样，**结构上不可能错**。到不了这层的服务才看下面。

**2. Schema 约束**：给模型函数/结构定义（Function Calling 的参数 schema、或 JSON Schema 贴 prompt）——模型"照着表格填空"比"自由发挥"稳得多。

**3. 解析层容错**：提取正文中的 JSON 段（剥掉 markdown 代码块围栏和废话）；解析失败**自动修复重试**（把报错原文喂回："你输出的 JSON 缺少右括号，请修正"——模型自我纠错的成功率出奇地高）；`json-repair` 类库兜底。

**4. 校验层**：解析成功 ≠ 内容合法——**zod/JSON Schema 验证字段和类型**，不合法同样带错误信息重试。

**工程实战模板**：JSON mode + Schema 声明 + 失败修复重试（上限 2 次）+ 校验放行——四层下来稳定率 99.9%+。

**一句话**："让模型输出 JSON 是概率问题，让它必然输出 JSON 是工程问题——**约束解码 > 提示词乞求 > 失败重试**"。
