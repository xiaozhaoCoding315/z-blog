question: Redis 单线程为什么还这么快？

**先澄清**：说"单线程"指的是**处理网络请求和读写数据的主线程**——持久化（fork 子进程）、异步删除这些另有线程。

**快的四个支柱**：

1. **纯内存操作**：内存纳秒级 vs 磁盘毫秒级——快 5 个数量级，这是地基
2. **单线程免锁**：没有锁竞争、没有上下文切换的开销——多线程的"协调成本"全省了
3. **IO 多路复用**：epoll 一个线程监听几万个连接——谁就绪处理谁，不傻等（Nginx 同款思路）
4. **数据结构为内存定制**：SDS（O(1) 拿长度）、跳表、intset——读写路径全是精心打磨过的

**单线程的瓶颈**：某个命令慢，全体排队——所以 Redis 有"慢命令黑名单"：KEYS *（全量遍历）、大 key 的 DEL、SMEMBERS 百万元素。**生产禁用 KEYS，用 SCAN 分批**。

**6.0 的多线程**：只把**网络 IO 的读写/协议解析**并行化（最耗 CPU 的部分），**命令执行依然单线程**——既保无锁简单性，又突破网络吞吐上限。答出这个"多线程但只多在 IO"的细节是加分项。

**一句话**：内存快 + 不折腾（无锁无线程切换）+ 数据结构狠活 = 单线程也碾压。
