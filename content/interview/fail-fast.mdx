---
question: 什么是 fail-fast？ConcurrentModificationException 是怎么触发的？
category: Java 集合
difficulty: 易
tags: [fail-fast]
---
这题每个人都踩过坑：一边 for-each 一边 remove，程序当场抛 ConcurrentModificationException——这就是 fail-fast 在工作。

**它是怎么发现的？**（原理一句话就懂）ArrayList 里有个修改次数的计数器 modCount。你创建迭代器时，它偷偷记住当前的次数；之后每次取下一个元素前对一下账："集合被改过的次数和我记的一样吗？"不一样说明**有人在我遍历期间动了集合**，立刻抛异常——宁可崩溃也不让你拿到错乱的数据，这就是 fail-fast（快速失败）的思想。

**那遍历时想删除怎么办？** 三种正路：

```java
// 1. 迭代器自己的 remove（会同步更新账本，安全）
Iterator<String> it = list.iterator();
while (it.hasNext()) {
    if (it.next().isEmpty()) it.remove();
}

// 2. JDK8+ 一行搞定（内部就是安全版迭代器）
list.removeIf(String::isEmpty);

// 3. 并发场景：用写时复制的 CopyOnWriteArrayList
```

**一个冷知识**：删"倒数第二个元素"时不会抛异常——因为删除后游标恰好和 size 相等，hasNext 返回 false，对账环节被跳过了。面试聊到这个细节会显得你真踩过坑。
