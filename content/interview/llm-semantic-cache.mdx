**LLM 调用又慢又贵**——同样的问题天天有人问，每次都重新生成是烧钱。缓存怎么做分两级：

**1. 精确缓存**：问题原文做 key（hash）→ 答案存 Redis——**实现最简单，但"Java HashMap 原理"和"讲讲HashMap"是两个 key**，命中率感人。

**2. 语义缓存（本题主角）**：新问题先 **embedding 向量化**，和缓存里历史问题的向量算相似度——**相似度 > 0.95 视为同一个问题**，直接返回缓存答案。"怎么部署网站"命中"网站如何上线"的缓存——**懂意思的缓存**。

**工程三件套**：
- 缓存 key = 问题向量 +（可选）上下文标签——存向量库（pgvector 就行）
- **阈值调优**：太低（0.85）误命中返回错误答案；太高（0.99）命中率惨——**按业务试 0.92~0.96**
- **失效策略**：知识更新（文档改了）相关缓存批量失效；对话型答案（带用户上下文）**别缓存**

**能缓存的另一头——Prompt 前缀缓存**：长系统提示（几十 KB 的知识/规则）+ 短问题的场景，**主流 API 支持 prompt caching**——前缀相同的部分计费打 1~2.5 折。把稳定内容放前面、变化内容放后面，自动享受。

**点睛**："语义缓存把命中率从'一字不差'提升到'意思相近'，配合 prompt 前缀缓存——**成本砍 50%+ 是常态**"。
