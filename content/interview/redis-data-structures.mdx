**五大类型配场景，重点讲 ZSet**（面试最爱）：

- **String**：缓存 JSON 对象、计数器（阅读量 INCR）、分布式锁
- **Hash**：一个 key 管一坨字段——购物车（用户下的每个商品对应数量），比 String 存整个 JSON 好在能单独改一个字段
- **List**：双端队列——最新动态、简单消息队列
- **Set**：无序去重——抽奖去重、共同关注（SINTER 交集一秒出）
- **ZSet**：**带分数的有序集合——排行榜专属**

**ZSet 为什么用跳表不用红黑树**（高频追问）：跳表 = 链表加了"高速公路层"，查找从顶层跳到底层 O(logN)；范围查（ZRANGE 取前 100 名）定位到起点后顺着底层链表直接滑下去，红黑树要中序遍历麻烦得多；而且跳表实现简单、还能通过节点稀疏控制内存。同时 ZSet 里还**并排藏了个哈希表**专管 O(1) 查"某人多少分"——一个类型两套索引，各干各的。

**三个加分结构**：Bitmap 位图（365 位存全年签到，1 人 1 年才 46 字节）、HyperLogLog（亿级 UV 统计，标准误差 0.81%，固定 12KB）、GEO（附近的人）。

**点睛**：Redis 单线程还快，一半功劳在数据结构设计——这些结构全是内存友好型的。
