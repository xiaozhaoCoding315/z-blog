**核心结构**：邀请码 → 绑定信息（谁生成的、有效期、用途、使用上限）→ 使用记录（谁用了、什么时候）。

**生成**：**随机短码**（6-8 位 base62）撞唯一索引重试；或**ID 加密变换**（雪花 ID 经 Feistel/哈希打散再 base62——**不可被枚举**且不重复，无需查库去重）。**千万别用自增序号**——竞对从 000001 挨个试能把你的活动羊毛薅秃。

**兑换的原子性**（一码一人次）：

```sql
UPDATE invite_code SET used_count = used_count + 1
WHERE code = ? AND used_count < max_count AND expire_at > now()
```

条件更新一步完成"验证+占用"——并发兑换天然串行。

**防枚举三层**：
1. 码空间要大（8 位 base62 = 218 万亿，暴力枚举不可能）
2. **失败限频**：单 IP/单账号连续错 5 次锁定+验证码——防脚本试码
3. 码混淆：不放"顺序感"的码（用户会猜下一个）

**防刷（拉新场景）**：同设备指纹限领、新注册账号风控（手机号段/行为特征）、**奖励延迟发放**（T+1 结算，作弊账号来不及提现就被封）。

**一句话**："兑换码系统 = **随机不可预测的码 + 数据库条件更新的原子占用 + 限频防试 + 延迟结算防薅**"。
