question: HyperLogLog 是什么原理？亿级 UV 统计为什么 12KB 就够？

**先看需求**：统计页面每天的 UV（独立访客数）。HashSet 存 1 亿个 uid 要 1GB+；**HyperLogLog 只要 12KB，标准误差 0.81%**——这不是魔法是概率统计。

**核心思想——"抛硬币推断"**：让每个 uid 哈希成一串 0/1，观察**开头连续 0 的最大长度 k**。直觉：如果见过连续 10 个 0，说明你大概率抛了很多很多次（2^10 量级）——**用"最罕见的事件"反推总量**。HyperLogLog 把数据分到 16384 个桶，各桶记各自的"最长连续 0"，最后调和平均汇总（消除单桶运气偏差）。

**误差的来历**：概率估计天然有方差——0.81% 对绝大多数 UV 场景毫无影响（你会关心 UV 是 1,000,000 还是 1,008,100 吗？）。

**用法三连**：`PFADD page:uv:2024-01-01 uid1 uid2` → `PFCOUNT page:uv:2024-01-01` → `PFMERGE` 合并多天。**注册即固定 12KB，1 亿用户也是 12KB**。

**选型对比**：要精确 → Set/Bitmap（Bitmap 还要求 uid 可转整数）；要省内存不在乎 0.8% 误差 → HLL。**点睛**："用 0.81% 的误差换 5000 倍内存，UV 这种场景稳赚"。
