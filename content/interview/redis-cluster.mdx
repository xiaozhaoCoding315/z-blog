**先分清两件事**：主从+哨兵解决的是**高可用**（挂了自动换）；Cluster 解决的是**容量和写性能**（一台装不下/写不动了）。别一上来就 Cluster。

**主从 + 哨兵**：一主多从复制读写分离；哨兵集群盯着主库，心跳丢了就开会投票选新主，应用自动切——数据没多，只是不怕挂。

**Cluster 的分片玩法**：把 16384 个**槽（slot）**分给多个主节点，每个 key 按 `CRC16(key) % 16384` 落进某个槽——数据就散到多台机器了。节点之间用 gossip 协议互相通信，某主挂了，它的从自动顶上。

**两个必考细节**：

1. **MOVED/ASK 重定向**：客户端请求发错节点，节点回 MOVED 告诉你"这个 key 在隔壁，顺便记住映射下次直接去"；**迁移期间**回 ASK（"临时在隔壁，就这次"）。聪明客户端（Jedis/Lettuce）本地缓存槽位表，基本一击命中
2. **多 key 操作限制**：mget/事务要求 key 在同一个槽——用 **hash tag** 破解：`{order1001}:a` 和 `{order1001}:b`，花括号里相同的 key 强制同槽

**说清一个权衡**：Cluster 的复制是**异步**的——主挂的瞬间，最新几条写入可能没来得及同步就丢了。它要的是可用性和扩展性，不是强一致。**至少 3 主 3 从起步**。
