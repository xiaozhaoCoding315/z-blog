**为什么不能用自增**：分库后两个库各自增会撞车；连续订单号还泄露业务量（竞对按号算你单量）。

**方案**：
1. **UUID**：本地生成无依赖，但**完全无序**——做 MySQL 主键会让 B+ 树疯狂页分裂，性能崩。适合当 traceId 不适合当主键
2. **雪花算法（重点）**：64 位 = 1 符号位 + **41 位毫秒时间戳**（够用 69 年）+ **10 位机器 ID**（1024 台）+ **12 位序列号**（单机每毫秒 4096 个）。趋势递增（B+ 树友好）、本地生成不依赖 DB
3. **号段模式**（美团 Leaf）：DB 一次批发 1000 个号到内存慢慢发，用完再取——DB 压力骤减
4. Redis INCR：简单但把命脉押给 Redis

**雪花的命门——时钟回拨**：NTP 校时往回调，同一毫秒序列号重来 → **ID 重复**。对策：检测到回拨拒绝发号等追平 / 小回拨自旋等待。生产直接用 Leaf 或 uid-generator，别裸写。
