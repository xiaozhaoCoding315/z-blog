---
question: 给 LLM 设计工具（Function Calling）的最佳实践？
category: Agent / LLM 应用
difficulty: 中
tags: [工具调用, Function Calling]
companies: [字节]
---
**七条实践**：
1. **工具描述写给模型看**：说清"什么时候该用我"和输入输出语义，而非给人看的 API 文档
2. **参数越少越稳**：枚举优于自由字符串；必填/可选明确
3. **返回可行动的错误信息**：「city 参数需包含省市」优于「invalid input」——模型能自我修正的前提是看得懂错在哪
4. **输出要精炼结构化**：截断大结果（摘要 + 总数），别把 1 万行塞进上下文
5. **危险操作加确认**：写操作/删除/支付——人工审批门（Human-in-the-loop）
6. **权限最小化**：每个工具白名单资源，工具内做鉴权而不是信任模型
7. **超时与幂等**：模型可能重试调用，工具必须幂等

**反模式**：一个"万能工具"塞 50 个参数；错误返回自然语言段落模型读不懂；让模型自由拼接 SQL（注入温床）。
