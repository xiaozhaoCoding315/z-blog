**核心矛盾**：瞬时流量（10 万 QPS）vs 库存少（100 件）——**让 99.9% 的流量在最外层被拒绝**。

**分层削峰**：
1. **前端**：按钮置灰/答题验证码错峰、URL 加时间戳盐防提前脚本
2. **网关层**：限流（令牌桶）+ 黑名单 + 用户级频控
3. **应用层**：**Redis 预扣库存**（Lua 原子判断+扣减），库存扣完直接拒绝——DB 几乎无压力
4. **异步下单**：扣减成功发 MQ，订单服务慢慢落库，前端轮询结果
5. **DB 兜底**：乐观锁 `UPDATE stock SET n=n-1 WHERE id=? AND n>0` 防超卖

**防超卖双保险**：Redis Lua 判扣原子性 + DB 条件更新。**防黄牛**：一人一单（Redis set 记 uid）+ 风控。

**对账**：Redis 扣减数 = 订单数 + DB 库存，定时校验补偿。
