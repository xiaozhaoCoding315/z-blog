**核心链路**：
1. **发号**：长 URL → 全局唯一 ID（号段/雪花/自增）
2. **编码**：ID 转 62 进制（a-zA-Z0-9，6 位可表达 568 亿）得到短码
3. **存储**：短码 → 长 URL 映射（MySQL 分片键=短码首字符；热点可 Redis 缓存）
4. **跳转**：访问短链 → 302 重定向（302 可统计每次点击，301 浏览器缓存后失去统计）

**关键设计点**：
- **302 vs 301**：要点击分析用 302；永久内容省流量用 301
- 自定义短码：预留命名空间 + 唯一索引冲突重试
- 缓存穿透：不存在的短码缓存空值 + 布隆过滤器
- 高 QPS 读：多级缓存 + CDN，读扩展靠副本

**追问预案**：预估量级怎么做（每日点击 PV / 读写比 100:1）、为什么不用哈希（冲突处理复杂且不可逆，发号天然唯一）。
