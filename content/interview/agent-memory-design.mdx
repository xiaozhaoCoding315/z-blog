question: Agent 的记忆系统怎么设计？短期记忆和长期记忆怎么配合？

**LLM 天生金鱼——每次调用都是失忆重生**。记忆系统就是给它配的"外挂大脑"，分三层：

**1. 工作记忆（当下这轮）**：当前上下文窗口里的对话和工具结果——**容量有限**，靠"滑动窗口+及时摘要"管理（重要的提炼留下，原文滚出窗口）。

**2. 短期记忆（本次会话）**：跨多轮的会话状态——用户偏好（"用户喜欢简洁回答"）、已确认的事实、任务进度。存 Redis/内存，会话结束可归档。**形式上常做成 key-value 事实表**："用户名=张三；目标=订机票；已选=周五早班"——每轮注入，比塞完整历史省 token 且不跑偏。

**3. 长期记忆（跨会话，越用越懂你）**：从历史会话中**沉淀的稳定知识**——用户画像（常出差、偏好靠窗）、领域事实（"该公司用 MySQL 8"）。**写入要克制**（信息抽取任务专门负责：什么值得记？冲突的旧记忆要更新），**检索按需**（当前话题相关才注入，别全塞）。

**写入与遗忘**：不是所有经历都值得记——**显式写入**（任务完成时总结沉淀）优于全量记录；记忆要有置信度和时间戳，**过期的淘汰**（公司半年前用 MySQL 现在换了 PG——旧事实要能被新事实覆盖）。

**点睛**："记忆设计的核心不是'存多少'而是'**该记什么、何时取、怎么忘**'——跟人类记忆一样，贵在筛选"。
