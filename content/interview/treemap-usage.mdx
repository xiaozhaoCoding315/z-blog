这题考的是"你知不知道 HashMap 办不到什么事"。

**HashMap 的短板**：它是散着存的，你问它"给我分数在 80 到 90 之间的人"，它只能把所有东西倒出来挨个筛。TreeMap 不一样——它内部是棵**红黑树**（一种自动保持平衡的二叉搜索树），存进去就是**排好序**的，范围查询是它的看家本领。

**红黑树是啥，一句话**：一棵会自己"调整坐姿"的搜索二叉树——左右高度差太多就转一转、换换颜色，保证最长路不超最短路两倍。这样查找、插入、删除稳定在 O(log n)，不会退化成链表。（为什么不用更"完美"的 AVL 树？AVL 调整得更频繁，插入删除代价比红黑树高，工程上红黑树更划算——Linux 内核、Java 都选它。）

**TreeMap 能干什么 HashMap 干不了的**：

```java
treeMap.subMap(80, 90)      // 分数 80~90 的人，直接切一段出来
treeMap.floorKey(89)        // 不超过 89 的最大分数（找最近邻）
treeMap.headMap(60)         // 挂科名单（小于 60 的）
```

**实际用在哪**：排行榜（分数→用户的有序表）、定时任务的时间轮、一致性哈希找"顺时针最近节点"。一句话：**要排序、要范围查，才想起 TreeMap；日常 KV 还是 HashMap**。
