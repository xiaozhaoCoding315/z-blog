---
question: 一次 HTTP 请求在 Spring MVC 里的完整流程？过滤器和拦截器的区别？
category: Spring
difficulty: 中
tags: [SpringMVC]
---
**流程当故事讲**：请求进来，**DispatcherServlet（大堂总管）**接客 → 问 **HandlerMapping（前台查号台）**："这个 URL 归谁管？"拿到对应的 Controller 方法和拦截器链 → 交给 **HandlerAdapter（翻译官）**去真正调用（参数解析、数据绑定都是它做）→ Controller 返回结果 → @ResponseBody 的话走 HttpMessageConverter 把对象序列化成 JSON；返回视图名则找 ViewResolver 渲染。

**过滤器 vs 拦截器**（必考对比）：

- **过滤器是 Servlet 亲儿子**：在请求进 Spring 之前就工作，拿得到原始的请求流——所以编码、CORS、XSS 过滤必须它做
- **拦截器是 Spring 的员工**：知道你调的是哪个 Controller 哪个方法——登录校验、权限、日志埋点用它更顺手

**执行顺序记这条链**：Filter 前 → 拦截器 preHandle → Controller → 拦截器 postHandle → Filter 后。**坑点**：Controller 抛异常时 postHandle 不执行，afterCompletion 永远执行——所以清理资源要放 afterCompletion。
